# 记忆中枢（memory-hub）

按项目分库的本地长期记忆插件。让代理记得住这个仓库怎么分工、上次为什么那么定、
哪些坑踩过——而且这些记忆会自己合并、加权、淘汰，不是一个只进不出的流水账。

资源版本 **0.2.0**，许可证 **MIT**。

## 安装后提供什么

- **`memory` MCP server**（零依赖 stdio）：八个工具
  - `retain` —— 写一条结论（自动去重合并、自动脱敏）
  - `recall` —— 按查询取回，命中会强化该条目
  - `reflect` —— 按类型组装证据包，并列出被推翻的旧结论
  - `memory_edit` —— 改 / 失效 / 恢复 / 归档 / 删除
  - `stats` —— 库概况、容量、热门标签、项目归属来源
  - `history_digest` —— 有界读取会话摘录，作为巩固素材（默认只取当前对话）
  - `memory_maintain` —— 手动跑一次衰减与淘汰
  - `memory_purge` —— 移到回收站（不是直接删除）
- **两个技能**：`memory-recall`（何时取回、怎么用结果）、`memory-curate`（怎么收敛地整理）
- **两条命令**：`/memory`（stats / load / consolidate / tidy / clear）、`/remember`（快速记一条）

## 依赖与生效方式

- **Node.js ≥ 18**：MCP server 由宿主用 `node server/memory-hub.mjs` 启动；插件不附带 Node.js。
- 安装后按宿主提示重启会话，让 MCP 启动；用 `/mcp` 检查 `memory` 是否加载。
- 工具实际注册名取决于宿主，通常是 `memory-hub__memory__retain` 这种形式，以 `/mcp` 列出的为准。
- 技能与命令按宿主提示重载会话。
- 不需要配置、不需要 Key、不需要登录、不产生费用。

## 数据放在哪

```
~/.stepcode/agent/memories/
  --D--AgentPrograms-my-repo--/
    memory.json              项目库
  _global/
    memory.json              跨项目偏好
```

目录名与 DFSC 会话目录同一套规则，方便你把它和会话一起备份或一起清理。
用 `MEMORY_HUB_HOME` 可整体改位置；`stats` 会回报实际路径。

**「记忆」不是安全存储**：它就是明文 JSON 文件，任何能读你用户目录的程序都能读。
写入时会脱敏常见凭据形态（`sk-…`、`ghp_…`、`AKIA…`、`Bearer …`、`*_API_KEY=…`、
PEM 私钥块、长十六进制串），但**不要**主动往里写密钥。

## 自进化是怎么发生的

不需要模型，全部是确定性规则（常数在 `server/evolve.mjs` 顶部）：

| 机制 | 触发 | 效果 |
| --- | --- | --- |
| 合并 | 每次 `retain` | 同类型且差异极小（相似度 ≥ 0.92）的条目并入旧的，取较高重要度，返回 `merged` |
| 强化 | 每次 `recall` | 被返回的条目命中数 +1，有效权重按 `0.05·ln(1+hits)` 提升（封顶 1） |
| 衰减 | 每次 `retain` | 从未命中且超过 60 天 → `archived`（保留在文件里，召回默认不返回） |
| 失效 | `memory_edit invalidate` | 标记被推翻并记录 `supersededBy`，历史仍可查 |
| 淘汰 | `retain` 超过上限 | 项目库 600 条 / 全局库 300 条，按有效权重从低到高归档，条数写进返回值 |

阈值定在 0.92 是有原因的：中文按二字组切分，「构建用 pnpm」和「构建用 npm」相似度就有 0.83，
阈值再松一点就会把互相矛盾的结论合并，等于丢掉「后来改主意了」这件事。

## 检索是怎么排序的

**相关度是乘数，不是加数。** 分数 = `相关度 ×（重要度 + 新近度 + 标签）`。
早期实现把重要度和新近度当独立加分项，实测零重叠的条目也能拿 0.45 分
（查 `pnpm` 时一条完全无关的记忆排到第二），检索于是被重要度而非「是否讲到这件事」主导。

- **相关度**按 idf 加权：出现在越少条目里的词权重越高。「记忆」「文件」「用」这类词几乎每条都有，
  不该决定排名；`pnpm`、`memories` 这类区分词才是。
- **中文单字权重低于二字组**：单字几乎出现在每句中文里，只配单字等于没配。
- **标签参与检索**：手写的 `tags` 与正文一起被索引，也被一起用于估计 idf。
- **少量同义展开**（只在查询侧，不改存储）：`风格/喜欢 → 偏好/要求`、`踩坑 → 陷阱/注意`、
  `存哪/在哪 → 路径/位置` 等约十条。表刻意很小——宁可漏召回，不可乱召回。
- **相关度低于 0.12 的条目不返回**：查不到就是查不到，不拿高分噪声凑数。

实测（`node scripts/eval.mjs`，两个独立进程模拟两次会话）：10 条真实项目结论写入后，
8 条自然提问全部命中目标条目（含「用户喜欢什么风格」这类不含任何原词的问法），
2 条负样本（`数据库索引优化` 等）正确返回 0 条。

衰减和淘汰挂在写入路径上，所以一个项目长期无人写入时不会自行变化；
需要手动清理时调 `memory_maintain`（或 `/memory tidy`）。

## 项目归属怎么判断

MCP 进程的工作目录被宿主锚定到插件目录，拿不到用户项目路径，所以按顺序解析：

1. 工具参数 `project`（技能里要求每次都传——**这是唯一可靠的方式**）
2. 环境变量 `MEMORY_HUB_PROJECT`
3. 读 `~/.stepcode/agent/sessions/` 下最近修改的会话文件首行的 `cwd`
4. 回退 `_default`，`stats` 会显示 `source: "fallback"`

多开会话时第 3 步可能落到别的项目，所以代理写记忆时应该显式传路径。

## 权限与数据范围

- MCP server 以当前用户权限运行，只通过 stdio 与宿主通信，**不发起任何网络请求**。
- 只读写 `MEMORY_HUB_HOME` 与 `MEMORY_HUB_SESSIONS` 指向的目录；不读项目文件、不读凭据。
- `history_digest` 会读会话 `.jsonl` 的正文摘录（跳过子代理会话与工具输出，严格限长）。**默认只取最近 1 个会话**（当前对话）；要跨会话归纳时才显式传 `sessions`（最多 10）。
- 记忆按项目分库是**数据分区，不是访问控制**：能调用本插件的任何会话都能读同一个库。
- `memory_purge` 把文件改名为 `.trash-<时间戳>`，宿主卸载插件**不会**替你删这些文件。

## 费用

不调用模型，不消耗额度，不联网。唯一成本是磁盘（几百 KB 级别的 JSON）。

## 停用与清理

1. 在插件页停用或卸载，重启会话，MCP 进程停止。
2. 手动删除 `~/.stepcode/agent/memories/`（或 `MEMORY_HUB_HOME` 指向的目录），
   包括残留的 `.lock`、`.tmp`、`.corrupt-*`、`.trash-*`。
3. 卸载**不会**自动删除记忆文件——宿主只清理它自己登记的安装资源。

## 已知边界

- **没有自动注入**：DFSC 没有会话开始钩子，插件无法在开局把记忆塞进系统提示。
  「先 recall 再动手」由 `memory-recall` 技能提示代理执行，不是宿主保证的行为。
- **不调用模型**：`reflect` 只组装证据不生成结论；`history_digest` 只摘录不摘要。
- **不做向量检索**：分词是「拉丁整词 + 汉字单字与二字组」，语义相近但用词不同的条目可能取不到。
- **数字不同就不合并**：`监听端口 3000` 改成 `3001`、`超时 5 秒` 改成 `30 秒` 都会保留成两条。这是有意的——数值差异往往就是「后来改主意了」，合并会把新值抹掉。纠正旧结论用 `memory_edit invalidate` 并记 `supersededBy`，不要指望被合并掉。
- **项目分库按本机路径字符串算**：`projectSlug` 走宿主的路径解析，所以同一个仓库在 Windows 与 macOS/Linux 上会得到不同 slug，记忆库分成两份、互不可见。与宿主会话目录保持一致优先于跨平台一致；跨机器共享记忆需要手动同步文件（见「数据放在哪」）。
- **不做桌面入口**：没有声明 `desktop`，不要求新版宿主构建。
