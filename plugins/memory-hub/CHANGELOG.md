# 变更记录

## 0.2.0 — 工程性加固

这一版没有新功能，全部来自实机测试中暴露出来的问题与实际崩溃风险。
每条都带回归测试，`node --test` 106 项。

### 修复：检索质量

- **相关度改为乘数**（`evolve.mjs`）。原实现把「重要度 + 新近度」当独立加分项，
  导致零重叠的条目也有约 0.45 底分。实测查 `pnpm` 时一条完全无关的记忆排到第二。
  现在是 `相关度 × 质量`，不相关条目降到 0.02。
- **按 idf 加权**。中文里「记忆」「文件」「用」这类词几乎每条都有，按余弦算它们
  吃掉了大部分分数。现在出现在越少条目里的词权重越高。
- **中文单字权重降为二字组的 0.35**。单字几乎出现在每句中文里，只配单字等于没配。
- **标签参与检索**。`tags` 与正文一起被索引、一起参与 idf 估计，手写关键词可被搜到。
- **少量同义展开**（仅查询侧，约十条）。`风格/喜欢 → 偏好/要求`、`踩坑 → 陷阱/注意`、
  `存哪/在哪 → 路径/位置`。表刻意很小：宁可漏召回，不可乱召回。
- **相关度低于 0.12 不返回**。查不到就是查不到，不用高分噪声凑数。

实测（`scripts/eval.mjs`，两个独立进程模拟两次会话）：10 条真实结论 → 8 个自然提问
全部命中（含不含任何原词的问法），2 个负样本正确返回 0 条。

### 修复：检索质量（重启后实测补修）

- **查询碎片不再稀释分母**。中文按二字组切分，一句问法会带出「户喜」「欢什」「么风」
  这类只属于这句话的碎片；它们不可能命中任何条目，留在分母里会把真正的命中摊薄到
  门槛以下（实测「用户喜欢什么风格」从命中变成查不到）。现在分母只统计库里确实
  出现过的词。
- **停用词只作用于单字**。早期版本把「含停用字」的二字组也剔除，结果 `用户`、`要求`、
  `偏好` 这些有区分度的词被一起删掉。
- **单字偶然命中大幅打折**。「数据库索引优化」里只有「数」在库中出现过（在「工具参数」
  里），却曾算成 1.000 满分、返回 3 条无关结果。只有单字命中时相关度 × 0.25。
- **`reflect` 与 `recall` 用同一道相关度门槛**。`reflect` 原来只排序不过滤，
  证据包里会混进只共享一个通用词的条目（实测 0.033 分的那条被当成「相关证据」）。

### 修复：检索质量（第二次重启后补修）

上一轮把「单字命中」改成 ×0.25 折扣仍不够：门槛 0.12 之下，折扣后 0.125 的噪声
照样越线返回，而且这些噪声条目会被记命中、长期强化。

改成结构性规则：**查询与记忆只共享单个汉字时，相关度直接为 0**。
不再靠常数调节——中文单字偶然重合太常见（「数据库索引优化」与「工具参数」共享 `数`，
与「重新」共享 `库`），它们不该算任何程度的相关。

- 新增 `isDistinctive(token)`：拉丁整词或中文二字组才算有区分度。
- `relevance` 要求至少一个区分词命中，否则返回 0。
- 移除 `SINGLE_CHAR_ONLY_PENALTY`（被上述规则取代）。
- 实测：`数据库索引优化` / `量子色动力学` / `区块链共识算法` 三个负样本全部返回 0 条；
  真实查询仍命中 0.797。

### 修复：存储一致性

- **`read()` 不再返回陈旧缓存**。文件被删除后仍返回旧内容，会让 `purge` 之后
  继续显示已清空的条目。现在删文件即清缓存。
- **`purge` 在锁内完成计数与改名**。原实现先 `read` 再 `rename`，间隙里别的会话
  写入会让「移走 N 条」的 N 与实际文件对不上。
- **新增 `inspect(fn)`**：持锁只读，供「读完要基于它删文件」的路径使用。
- **库文件大小上限 16 MiB**：超限读路径报 `corrupt`、写路径拒绝写入，不再把
  异常大的文件整体读进内存。
- **损坏备份名不再残留**：只有真正损坏时才指向备份文件，一次健康写入后清空。

### 修复：记忆语义

- **合并分支也跑衰减与淘汰**。原实现只在新增分支执行，于是「一直在合并」的项目
  （同一主题反复写入）永远不会清理过期条目。
- **只有一个分支做收尾**：`settle()` 统一处理衰减 + 淘汰 + 更新时间戳。
- **命中只记给返回的条目**。原实现给所有「匹配」都 +1，等于没返回的条目也在被强化，
  权重长期失真。现在先无锁打分，再只对最终 `slice(0, limit)` 的条目写命中。
- **纯查询不再写盘**：无匹配时不会产生任何写入。
- **`memory_edit` 跨库定位**：不传 `scope` 时先查项目库、再查全局库。
  原实现只能改项目库，用户拿到全局记忆的 id 永远改不了。
  `not_found` 会返回 `searched` 说明查过哪些库。
- **`source` 去重并限长**：原实现用子串判断，`session:a` 与 `session:a,b`
  互相包含，反复合并后变成越来越长的重复串。现在按条目去重、最多 4 条。
- **合并保留干净文本**：先比归一化后的长度，等长保留先写下的那条，
  不让手滑多加的空格赢过干净版本。
- **状态过滤去冗余**：`recall` 原有两个互相覆盖的状态判断。

### 修复：会话摘录

- **预算按剩余文件数分配**。原实现用 `(files.length - sessions.length)`，
  一个空会话就会让后面的文件多分预算并整体溢出。
- **空会话不再跳过**：记录 `messages: 0`，让调用方知道扫到了但没内容。
- **会话头也计入预算**：只有正文时才不会超 `maxChars`。
- **单会话文件上限 32 MiB**：超过直接跳过，不读进内存。

### 修复：协议健壮性

- **单请求失败隔离**：一个工具调用出错不影响后续请求（回归测试覆盖）。
- **缺失 `method` 的有 id 请求回 `-32600`**，不让调用方干等一个永不到来的响应。
- **工具参数必须是对象**，否则回 `-32602` 且不触碰存储。
- **工具调用 25 秒超时**：磁盘或锁出问题时明确失败，不让整个模型回合挂住。
- **优雅关闭**：stdin 关闭 / SIGINT / SIGTERM 时等当前请求做完再退出，
  避免中途被杀留下 `.tmp` 与 `.lock`。
- **兜底异常处理**：`unhandledRejection` / `uncaughtException` 记 stderr，不静默死亡。

### 新增

- `scripts/eval.mjs`：两次会话（两个独立进程）的检索效果评估，8 正样本 + 2 负样本。
- `tests/protocol-robustness.test.mjs`：6 项协议健壮性测试。
- `tests/store.test.mjs` 新增 9 项：命中计数、合并分支衰减、全局库编辑、
  source 去重、干净文本合并、损坏库清空等。

### 已知边界（未变）

- 没有自动注入：DFSC 没有会话钩子，「开局 recall」靠技能提示，不是宿主保证。
- 不调用模型：`reflect` 只组装证据，`history_digest` 只摘录。
- 不做向量检索：语义相近但用词完全不同的条目取不到。
- 本机安装的是官方 StepFun 0.4.1 外壳，没有插件中心，UI 安装验收无法完成。
