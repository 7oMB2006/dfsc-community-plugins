# BVR 视频研究

Bilibili Video Research 的 DFSC 配套资源，版本 `0.1.1`。提供：

- BVR MCP 启动声明，工具包括 Bilibili 研究、本地视频分析和精确片段检查。
- `bilibili-video-research` 研究技能，区分语言、画面和多模态证据。
- `/bvr` 提示命令与项目标识图标。

来源：`7oMB2006/Bilibili-Video-Research` 的
`plugins/bilibili-video-research`。完整来源提交和逐文件哈希见市场根目录
`registry.json` 与 `registry.lock.json`，资源由同步工具生成。

项目文档、问题反馈链接展示为卡片，社区视频展示为教程。
正文中的普通链接保持正文链接，其中的技术说明入口指向本市场审核的本页。
分类校验已由社区市场 PR #3 合入；作者声明与市场登记保持各自单一来源。

## 准备与安装

1. 在插件目录以外准备包含 DFSC 适配代码的 BVR checkout。
   按 BVR 项目说明安装 Node.js 24+，运行 `npm ci`、`npm run build`、
   `npm test`。不要省略 tsx 开发依赖。build 当前为类型检查，不产生 dist。
2. 在 DFSC 添加本社区市场，在「发现」安装 Bilibili Video Research。
   默认市场尚未包含此条目时，需等待收录合入并更新市场。
3. 支持新插件中心的宿主可进入「插件 → Bilibili Video Research → 配置」，
   选择 BVR 运行目录，检查环境并保存。运行目录需具有
   `dfscConfigurationVersion: 1` 标记和完整依赖。
4. 新建会话或按提示手动重启会话，使 MCP、技能和命令加载新配置。

资源安装不会下载 Node.js、克隆 BVR、安装 npm 依赖或执行安装脚本。
已有官方 DFSC 安装包不会因市场更新而自动获得新的宿主能力。
检查环境不请求模型，也不能证明 Key、账户、套餐或计费有效。

## 跟随 DFSC 会话

新宿主默认提供跟随模式。完成 DFSC 登录并选择当前会话模型后，首次模型请求
由宿主确认账户渠道、地区、模型及额度消耗；安装插件本身不等于授权计费。

- 仅使用当前会话已生效的 Step 账户、地区、API/Plan 渠道与兼容模型。
  未完成的登录选择不会生效，失败或拒绝授权不自动改走直调 API。
- 宿主在主进程代发请求，不向插件导出账户 Key 或登录 Cookie。
  MCP 声明里的 `bvr-managed-provider-context` 是阻止自动注入 Key 的非密钥占位。
- 一次研究固定账户/模型上下文。切换账户、渠道、会话或模型会令旧上下文失效；
  新研究重新确认。取消不能撤销提供商已接受请求的费用。
- 无字幕的音频转写使用专用 `stepaudio-2.5-asr` 模型，沿用所选地区与
  Plan/API 渠道的 ASR 地址；总结使用当前会话模型。失败不改走其他渠道。
  本次受控测试不代表真实 Plan ASR 可用性或计费已复测。
- 视频需要宿主确认模型支持；不兼容时要求用户选择，不自动换模型。
  单次媒体上限 23 MiB，大视频应指定较短片段。

该连接是同一系统用户下的受限本地集成，不是恶意插件的文件系统沙箱。
不要共享宿主 `bvr/host.json`，不要安装不可信的可执行资源。

## 独立配置

独立模式需用户明确选择，不是跟随模式出错后的自动回退。
新插件中心可分别填写主力模型和 ASR 的接口地址、API Key、模型名：

- 两组连接互不借用，保存的 Key 不回显；留空保留，输入新值替换。
- 当前图形表单支持阶跃官方地址与 Step ASR 协议。
  已有 Gemini 等非表单配置会保留，继续通过 CLI 维护。
- **独立模式不会跟随 DFSC 聊天账户切换**。费用按独立配置的渠道和凭据计算。

兼容宿主也可以通过 CLI 设置。将安装资源内的 `provider.example`
放到插件目录以外的私密位置，填写提供商及自己的 Key，再运行：

```powershell
node "<PLUGIN>/server/configure.mjs" --profile "<DFSC数据目录>/step-runtime" --runtime "<BVR本体绝对路径>" --mode independent --env-file "<私密配置文件绝对路径>"
node "<PLUGIN>/server/start.mjs" --check
```

`<PLUGIN>` 通常为 `<DFSC数据目录>/step-runtime/plugins/bilibili-video-research`。
参数全部使用本机绝对路径。已有配置默认拒绝覆盖，核对后才使用 `--replace`。
Step 必须明确指定 `CODEX_VIDEO_PROVIDER=stepfun`、`STEPFUN_API_KEY` 和
`STEPFUN_BASE_URL`：国内 API 为 `https://api.stepfun.com/v1`，Plan 为
`https://api.stepfun.com/step_plan/v1`；海外使用对应 `api.stepfun.ai` 地址。
启动器仅接受这四个官方 Step 地址，不因缺失配置补用宿主 Key。
Gemini 需显式选择 `CODEX_VIDEO_PROVIDER=gemini` 并提供自己的 Key。

独立 ASR 可另设 `STEPFUN_ASR_BASE_URL`、`STEPFUN_ASR_API_KEY` 和
`STEPFUN_ASR_MODEL`；前两者只设一项会拒绝请求。仅为兼容已有 CLI 配置，
两者均未设置时仍共用主力连接。插件中心始终写入两组独立连接。

配置保存在 Desktop 自有 `step-runtime/bvr/config.json` 及其引用的私密文件，
不在插件目录中。保存不会自动重启会话。配置变化后旧进程在下次模型请求前
拒绝继续运行，ASR 与总结之间也会检查；在途费用不能撤销。
原有 schemaVersion 1 配置继续保持独立模式，不自动改用宿主账户。

## 数据与权限

BVR 会访问 Bilibili、下载临时媒体，并可能将媒体、字幕、公开元数据和采样评论
发送给选定模型提供商，消耗其额度或余额。评论属于不可信辅助信息。
Cookie 仅使用用户明确提供的本地文件，不能绕过付费、私密或登录权限。
不要将 Cookie、Key、真实配置、会话或日志提交到插件资源目录。

高级设置包含 Cookie 文件、临时下载目录、下载代理和优先字幕。
每次研究分配独立临时目录并按 BVR 现有逻辑清理。
下载代理应用于 yt-dlp 探测和下载，不表示模型请求也通过该代理。
跟随模式忽略私密文件中的提供商 Key/地址/模型，也不加载 BVR 目录的 `.env`。

## 使用、更新和停用

示例：`/bvr <公开视频链接> 总结讲述内容，并区分证据与推断`。
MCP 标识为 `bilibili-video-research__bvr`。技能不保证对每个任务自动触发。

插件中心服务开关只停用 MCP，不移除技能或命令。卸载会移除资源和 MCP 声明，
按提示重新加载会话；不会删除外部 BVR 本体、私密配置或其他客户端的服务。
彻底清理由用户单独处理自己创建的私密文件。

更新市场不自动替换已安装副本，沿用当前宿主的卸载重装与会话重载流程。
BVR 本体在自己的项目内更新；资源更新不自动升级本体或 DFSC。
